# Архитектура приложения: taskbox-api (Простая версия)

**taskbox-api** — учебный API-сервис на FastAPI и SQLite для управления списком задач. Структура максимально упрощена: минимум файлов, понятное разделение кода и автоматическое создание базы данных при запуске.

---

## 1. Технологический стек

* **Фреймворк:** FastAPI
* **База данных:** SQLite 3 + SQLAlchemy (обычный синхронный режим, без сложных настроек)
* **Валидация:** Pydantic
* **Авторизация:** Простой JWT-токен (OAuth2PasswordBearer) + хэширование паролей (Passlib)

---

## 2. Файловая структура проекта

Все файлы лежат в одной папке `app` без глубокой вложенности.

```text
taskbox-api/
├── app/
│   ├── main.py          # Точка входа: запуск приложения и создание таблиц БД
│   ├── database.py      # Подключение к файлу SQLite (taskbox.db)
│   ├── models.py        # Таблицы базы данных (User и Task)
│   ├── schemas.py       # Схемы данных (что принимаем и что отдаем в JSON)
│   ├── auth.py          # Проверка паролей, создание JWT-токена и получение текущего юзера
│   └── routers/         # Папка с ручками (эндпоинтами)
│       ├── users.py     # Регистрация и вход (логин)
│       └── tasks.py     # Создание, просмотр, обновление и удаление задач
├── taskbox.db           # Файл базы данных (появится сам при первом запуске)
├── requirements.txt     # Список библиотек (fastapi, uvicorn, sqlalchemy, passlib, pyjwt)
└── ARCHITECTURE.md      # Этот файл с описанием
```

---

## 3. За что отвечает каждый файл

* **`database.py`** — создает движок SQLAlchemy, подключается к файлу `sqlite:///./taskbox.db` и дает сессию для работы с БД.
* **`models.py`** — описывает две таблицы: `users` и `tasks`. В `main.py` при старте вызывается `Base.metadata.create_all()`, поэтому миграции не нужны — таблицы создадутся сами.
* **`schemas.py`** — описывает правила проверки данных (например, что заголовок задачи не пустой, а пароль не возвращается в ответе).
* **`auth.py`** — содержит функции для шифрования пароля и зависимость `get_current_user`, которая по токену определяет, кто делает запрос.
* **`routers/`** — сами HTTP-запросы, разделенные на два файла для порядка: отдельно для пользователей, отдельно для задач.

## 4. Спецификация API (Все ручки)

### 4.1. Пользователи и вход (`/auth`)

| Метод | Путь | Описание | Что отправляем | Что получаем |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/auth/register` | Регистрация нового пользователя | `email`, `password` | Данные созданного пользователя (`id`, `email`) |
| `POST` | `/auth/login` | Вход в систему | `username` (email), `password` | `access_token` (JWT-токен) |

### 4.2. Задачи (`/tasks`)

Все ручки ниже требуют передачи токена (кнопка **Authorize** в Swagger UI). Пользователь работает только со своими задачами.

| Метод | Путь | Описание | Параметры / Тело запроса | Коды ответа |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/tasks` | Создать новую задачу | `title` (обязательно), `description` (опционально) | `201 Created` |
| `GET` | `/tasks` | Получить список всех своих задач | Опционально query-параметр `?is_done=true/false` | `200 OK` |
| `GET` | `/tasks/{task_id}` | Получить одну задачу по ID | `task_id` в пути | `200 OK`, `404 Not Found` |
| `PUT` | `/tasks/{task_id}` | Полностью обновить задачу | `title`, `description`, `is_done` | `200 OK`, `404 Not Found` |
| `PATCH` | `/tasks/{task_id}` | Частично обновить задачу (например, только статус) | Любое из полей: `title`, `description`, `is_done` | `200 OK`, `404 Not Found` |
| `DELETE` | `/tasks/{task_id}` | Удалить задачу | `task_id` в пути | `204 No Content`, `404 Not Found` |

## 5. Таблицы базы данных (`models.py`)

### Таблица `users`
* `id` — числовой ID (Primary Key)
* `email` — строка, уникальная
* `hashed_password` — зашифрованный пароль

### Таблица `tasks`
* `id` — числовой ID (Primary Key)
* `title` — заголовок задачи (строка)
* `description` — описание задачи (текст, может быть пустым)
* `is_done` — статус выполнения (`True` или `False`, по умолчанию `False`)
* `owner_id` — ID пользователя-владельца (`ForeignKey("users.id")`)
